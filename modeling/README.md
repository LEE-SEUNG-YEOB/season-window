# modeling: 기상 변수와 개화일 모델

B 담당 코드다

기상 일자료로 수목원 x 연도 변수를 만들고 개화일 모델을 검증해 고르고 화면이 쓰는 기능 함수(`season_functions.py`)와 그 함수가 읽을 표를 만든다

코드 주석의 절 번호(4절 2항 5절 4항 10절 등)는 B의 모델 설계서 절 번호다

4절 2항은 설계서의 4.2절이다

## 1. 두 가지 판

| 판 | 언제 | 결과를 쓰는 곳 |
|---|---|---|
| 정제본 | `data/interim/phenology_site_year.csv`가 있을 때<br>`weather_daily.csv`가 없으면 기온은 공개 기온(`data/external/kma_ta_daily.csv`)을 쓰고 강수와 일조는 비운다 | 3절의 자리 |
| 집계표(미리 보기) | 식물계절 정제본이 없을 때<br>A의 집계표(`reports/tables`)와 공개 기온(`data/external`)으로 돈다 | `data/processed/preview`에만 쓴다 |

- 판은 파일이 있는지로 저절로 정해진다(`mconfig.mode()`)
- 따로 고를 것이 없다
- 집계표 판은 화면 개발과 코드 점검용이다
- 이 판의 숫자는 제출물에 옮기지 않는다
- `reports/tables`도 건드리지 않는다
- 환경 변수 `SEASON_ROOT`를 주면 그 폴더를 저장소 맨 위로 보고 돈다
- 저장소 사본이나 점검용 자료로 돌릴 때 쓴다

## 2. 돌리는 법

저장소 맨 위에서 차례로 돌린다

```bash
python3 modeling/weather.py
python3 modeling/dataset.py
python3 modeling/baseline.py
python3 modeling/validation.py
python3 modeling/slopes.py
python3 modeling/service.py
python3 modeling/challenge.py
python3 modeling/revision.py
python3 modeling/tests.py
```

- 파일 이름에 번호가 없으니 위 순서를 지킨다(1단계 weather부터 8단계 revision까지)
- 이 문서의 1단계~8단계는 이 순서를 가리킨다
- Python 3.11과 pandas numpy scipy scikit-learn(4단계 랜덤포레스트)을 쓴다
- 함수 파일 `season_functions.py`는 pandas만 쓴다
- 대부분 몇 초 안에 끝난다
- 4단계가 랜덤포레스트 때문에 가장 길다(십여 초)
- 7단계는 십 초 안쪽이다
- 7단계는 2단계가 만든 학습 표와 정제본만 읽으므로 2단계 뒤라면 따로 돌려도 된다
- 8단계는 7단계가 쓴 파일만 읽는다(1초 안쪽)
- 6단계와 7단계와 8단계는 정제본 판에서만 표를 만든다
- 집계표 판에서는 안내만 하고 끝난다
- `tests.py`는 실패가 하나라도 있으면 끝 코드 1을 돌려준다

### 모듈 계층

| 층 | 파일 | 불러 쓰는 우리 모듈 |
|---|---|---|
| 설정 | `mconfig.py` | 없음 |
| 변수 | `features.py` | mconfig |
| 모델 | `models.py` `clock.py` | features mconfig |
| 단계 | `weather.py` `dataset.py` | features mconfig |
| 단계 | `baseline.py` `validation.py` `slopes.py` `service.py` | models mconfig |
| 단계 | `challenge.py` | clock models features mconfig |
| 단계 | `revision.py` | models features mconfig |
| 기능 | `season_functions.py` | 없음 |
| 점검 | `tests.py` | season_functions |

- 의존은 한 방향이다(단계 → 모델 → 변수 → 설정)
- 단계 파일끼리는 서로 부르지 않고 앞 단계가 쓴 파일만 읽는다
- 기능 함수는 파이프라인 모듈을 부르지 않고 표만 읽는다(`reference/station_map.csv`와 서비스 표 없으면 `reports/tables`의 집계표)
- 단계 파일은 저마다 `main` 하나로 들어간다

- 기준일마다 쓸 수 있는 변수가 정해져 있다(`features.USABLE`)
  - 2월 말: 기온_12월 기온_1월 기온_2월 기온_1_2월 기온_겨울_2월말 강수_1_2월 일조_1_2월 누적온도_5도_2월말
  - 3월 15일: 위에 누적온도_5도_3월15일을 더한다
  - 3월 31일: 전부
  - 4월 15일: M2만 쓰는 기준일이라 이 표의 변수를 쓰지 않는다(M2는 일자료에서 기준일까지의 누적온도를 바로 쌓는다)

- 어긋난 칸이 0이어야 한다
- 대구보정은 대구수목원 2009~2015년 줄(보정한 해)에서 True다
- 기상주의는 대아수목원 2025년 줄에서 True다(5절)
- 집계표 판과 `weather_daily.csv` 없이 돈 정제본 판은 공개 기온만 있어 강수와 일조 열이 비어 있다

### 대구(143): 기록이 바뀐 날은 2015년 6월 12일

- A의 문서(`docs/cleaning_rules.md` 2절 표의 대구 지점 줄, `docs/key_findings.md` "읽을 때 주의할 점"의 대구 줄)에는 2013년 9월에 관측 장소가 바뀌었다고 적혀 있었다
- 2013년 9월은 청사를 옮긴 때다(2013-09-30 신암동에서 효목동으로)
- 143번 기록은 그 뒤에도 2015년 6월 11일까지 옛 자리 값이다
- 두 줄은 B가 2026년 11월 19일에 고쳤고 고친 줄이 든 표와 목록 바로 아래에 주석을 달았다
- `docs/cleaning_rules.md`의 기간 숫자도 다시 냈다
- A의 방식(대구에서 대구를 포함한 연결 지점 10곳의 평균을 뺀 값)으로 공개 기온을 다시 계산하면 원래 숫자(2009년부터 2013년까지 1.8도 2015년 이후 1.0도)가 그대로 나온다
- 기간을 2009~2014년과 2016년 이후로 고치면 1.7도와 1.0도다
- 2015년은 두 자리 값이 섞인 해라 뺐다
- 근거
  - 기상청 화면의 안내문: "대구(유) 자료 확인 시 2015.6.12 이전 자료는 구청사(신암동)에서 관측한 자료입니다"
  - 지점 이력에 새 자리의 임시 지점 176이 2013-10-10~2015-06-11로 따로 올라 있다
  - 대구에서 나머지 아홉 지점의 중앙값을 뺀 값이 2015년 6월에 0.92도 내려간다(t -10.3)
  - 2013년 9월(-0.08도)과 지점 이력에 적힌 변경일 2017-08-25(+0.14도)에는 변화가 없다
- 크기: 두 자리에서 함께 잰 610일을 견주면 새 자리가 0.95도 낮다(표준편차 0.31)
- 달별로 -0.83~-1.10도다
- 영향: 고치지 않으면 2009~2015년 봄의 대구수목원 기온이 약 0.9도 높게 들어간다
- 개화일로 약 3일이다
- 기본 처리(`mconfig.DAEGU_ADJUST = True`)는 새 자리 기준으로 맞추는 것이다
  - 2013-10-10~2015-06-11: 176 지점 값을 쓴다
  - 2013-10-09까지: 옛 자리 값에 달별 평균 차이(새 자리 - 옛 자리)를 더한다
  - 2015-06-12부터: 그대로 둔다
- 176 값은 정제본(`weather_daily.csv`)에 있으면 그것을 없으면 `data/external/kma_ta176_daily.csv`를 쓴다
- 둘 다 없으면 `mconfig.DAEGU`의 달별 차이(같은 610일에서 구한 값)로 겹친 기간까지 맞춘다
- 집계표로 보면 보정 뒤 대구수목원만 본 상관(기온_2_3월)이 -0.62에서 -0.77로 좋아지고 전체 기울기는 -3.56에서 -3.57로 거의 그대로다
- 보정하지 않은 원값 결과와 대구수목원을 뺀 결과를 4단계 비교표에 민감도 줄로 함께 싣는다

### 그 밖의 것

- 기간 안(2009~2025년)에 지점 이력 변경이 있는 연결 지점은 대구와 수원뿐이다(진주는 2005년)
- 기록이 없는 작은 단차 후보(진주 2012년 5월 -0.46도 대전 2010년 11월 +0.41도 등)는 건드리지 않는다
- 일강수량 빈칸 108,773칸은 A의 정제에서 0으로 채워졌다(`docs/cleaning_rules.md` 2절 표의 일강수량 줄)
- 비가 오지 않은 날이 빈칸으로 오는 자료라 대부분 맞는 처리다
- 다만 결측 표시가 남지 않아 진짜 결측과 가릴 수 없고 누적 강수량이 조금 작게 나올 수 있다
- 빈칸으로 남은 것은 날짜가 통째로 없던 27일뿐이다(연결 지점에서는 춘천 3일 완도 2일 진주 2일)

## 6. 모델과 고르는 규칙

| 이름 | 내용 | 입력 |
|---|---|---|
| M0 | 조합 평균(학습 해만) | 없음 |
| M0r | M0 + 전국 최근 5년 편차 | 없음 |
| M1 | 조합 안에서 뺀 날짜를 조합 안에서 뺀 기온에 맞춘 공통 기울기 | 기온_2월 편차(주) 기온_1_2월과 기온_겨울_2월말(민감도) 기온_2_3월(상한) |
| RF | 랜덤포레스트(나무 500그루 잎 최소 40줄 조정 없음) | 2월 말까지 쓸 수 있는 넓은 입력 조합 평균 종 |
| M2 | 적산온도 시계에 그해 관측을 얹은 모델(아래 시계 모델 절) | 기준일까지의 하루 평균기온과 기준일까지 적힌 그해 관측 |

- 목표는 봄꽃 11종의 개화50%이상이다(8년 이상 조합 91개 1,311줄)
- 단풍은 단풍 5종의 단풍50%이상(19개 조합 224줄)으로 M0와 M0r만 견준다
- 이상치의심은 표시로만 옮기고 빼지 않는다(A와 같은 처리)
- 집계표 판의 학습 표는 A의 수목원 연도 효과 표와 전국 연도 편차 표로 만든다
- 검증
  - 한 해씩 빼기(주): 한 해를 통째로 빼고 나머지로 학습한다
  - 17번
  - 앞으로 가는 검증: 2015~2025년 각 해를 그 전 해만으로 예측한다
  - 11번
  - M0와 M0r은 여기서 견준다
  - 최근 4년 떼어 두기: 2022~2025년
- 고르는 규칙(결과를 보기 전에 정했다): 새 모델의 평균 절대 오차가 기준 모델보다 0.5일 이상 작고 이긴 해가 17해 중 13해 이상(앞으로 가는 검증이면 11해 중 9해 이상)이면 채택한다
- 판정은 `model_decision.csv`에 있고 함수가 그대로 읽는다
- 2월 말 줄에서 기준일 전에 이미 핀 줄은 평가에서 빼고 건수를 적는다
- 누출을 막는 장치
  - 조합 평균과 평년 기온은 언제나 그 fold의 학습 해로만 계산한다
  - 줄을 무작위로 나누지 않고 해를 통째로 나눈다
  - M0 M0r M1 RF의 입력은 기상 변수와 조합 평균과 종뿐이다
  - 그해의 관측은 기준일까지의 관측만 넣는다(M2만 쓴다)
  - 4단계에서 검증 해의 날짜를 999로 바꿔도 예측이 그대로인지 본다
  - 7단계에서는 검증 해의 기준일 뒤 관측 날짜와 기온을 999로 바꿔도 M2 예측이 그대로인지 본다
- 예측 범위는 예측값 ± t x 표준편차 x √(1 + 1/n)이다
- 기본은 80%다
- 기온 가정(temp_scenario)에 쓰는 기울기는 5단계에서 낸 기온_2_3월 전체 기울기(일/도)다
  - M1과 같은 식을 전체 해에 맞춘 값이다
  - 표준오차는 조합 수만큼 자유도를 뺀 잔차로 낸다
  - 종별 기울기는 해 수가 적어 참고로만 본다

### 시계 모델(M2): 먼저 적어 두는 것

- 그래서 아래 계산과 판정 방법과 `mconfig.py`의 M2 값을 실제 개화일로 채점하기 전에 적어 고정했다
- 코드(`clock.py` `challenge.py`)는 개화일을 가짜로 바꾼 점검용 자료로만 만들고 확인했다
- 실제 개화일 채점은 한 번만 했고 저장소에 올리기 전에 했다
- 채점 뒤에는 계산과 값과 판정 방법을 바꾸지 않는다
- 결과는 기각된 것까지 모두 표에 남긴다

### 시계 모델(M2): 계산

- 사건은 한 수목원 한 종 한 단계가 한 해에 관측된 날짜 한 줄이다
- 계열은 수목원과 종과 단계가 같은 사건 묶음이다
- 관측이 8해 이상인 계열만 쓰고 이상치의심 줄은 뺀다
- 시계
  - 2월 1일부터 하루 평균기온에서 5도를 뺀 값 가운데 0보다 큰 부분을 쌓는다(빠진 날은 0이고 대구는 보정한 값이다)
  - 계열의 요구량은 학습 해마다 그 단계가 관측된 날까지 쌓인 양의 평균이다
  - 시계 날짜는 그해 쌓인 양이 요구량에 닿는 날이다
  - 기준일까지 닿지 못했으면 학습 해마다 기준일 뒤로 늘어난 양을 이어 붙여 닿는 날을 구하고 그 중앙값을 쓴다(상한은 날짜숫자 212)
  - 그 사건의 해는 이어 붙이는 해에서 뺀다
  - 쌓인 양이 요구량과 같은 날은 닿은 날이다(백만분의 1도 안쪽으로 모자란 것은 같은 값으로 본다)
  - 반일로 적힌 날짜는 내림한 날까지 쌓인 양을 쓴다
  - 시계 편차는 시계 날짜에서 그 계열의 학습 해 시계 날짜 평균을 뺀 값이다(학습 해의 사건은 제 해를 뺀 평균과 견준다)
- 그해 관측
  - 이른 계열은 평년 날짜(학습 해 평균)가 기준일보다 7일 이상 앞서고 학습 해가 3해 이상인 계열이다
  - 기준일까지 온 사건은 평년보다 늦은 날 수를 쓴다
  - 아직 오지 않은 이른 계열 사건은 늦을 것으로 기대되는 날 수를 쓴다
  - 그 값은 표준편차 x φ(z) / (1 - Φ(z))이고 z는 (기준일 + 0.5 - 평년) / 표준편차다
  - 표준편차는 그 계열의 학습 해 표준편차이고 1일보다 작으면 1일로 둔다
  - 여기서 시계가 설명하는 몫(기울기 x 시계 편차)을 뺀 값이 시계가 못 맞춘 몫이다
  - 기울기는 기준일까지 온 이른 계열의 학습 사건을 원점을 지나는 직선에 맞춰 구한다
  - 학습 해의 사건은 제 해를 뺀 평균과 견준다
- 신호 넷(모두 시계가 못 맞춘 몫으로 만든다)
  - 전국: 그해 이른 계열 사건의 평균에 n / (n + 3)을 곱한 값(n은 사건 수)
  - 수목원: 같은 수목원 다른 종의 평균에서 전국 평균을 뺀 값에 n / (n + 3)을 곱한 값
  - 꽃눈파열: 같은 수목원 같은 종의 그해 꽃눈파열 사건 값
  - 개화시작: 같은 수목원 같은 종의 그해 개화시작 사건 값
  - 꽃눈파열과 개화시작 신호는 그 계열의 학습 해가 3해 이상이고 그 사건이 기준일까지 왔거나 이른 계열일 때만 쓰고 아니면 0이다
- 가운데는 조합 평균에 시계 편차와 신호 넷을 저마다 이득을 곱해 더한 값이다
- 폭은 기존 폭(조합 표준편차 x √(1 + 1/n)이고 최소 1일)에 상태별 배수를 곱한 값이다
- 상태는 셋이다
  - 앞 단계 없음: 기준일까지 같은 수목원 같은 종의 꽃눈파열도 개화시작도 보지 못했다
  - 꽃눈파열 봄: 꽃눈파열만 봤다
  - 개화시작 봄: 개화시작을 봤다
  - 학습 해가 3해에 못 미치는 계열의 사건은 본 것으로 세지 않는다
- 이득 다섯과 폭 배수 셋은 fold마다 학습 줄 가운데 그해 기준일에 아직 피지 않은 줄로 구한다
  - 기준일 + 0.5에서 아래를 자른 정규 분포의 가능도가 가장 큰 값이다(L-BFGS-B이고 이득 0과 배수 1에서 시작한다)
  - 이득은 0~1.5이고 폭 배수는 0.3~1.3이다
  - 값이 0이 아닌 학습 줄이 30줄에 못 미치는 신호의 이득은 0이다
  - 학습 줄이 30줄에 못 미치는 상태는 앞 단계 없음 상태의 배수를 쓴다
- 예측은 기준일 + 0.5에서 아래를 자른 분포의 중앙값이고 80% 범위는 10%와 90% 분위다

## 7. 기능 함수(season_functions.py)

화면(`service/app.py`)이 불러 쓴다

함수 이름과 인자와 반환 키는 두 판에서 같다

| 함수 | 쓰임 |
|---|---|
| `sites()` | 지도에 찍을 10곳 |
| `catalog(site, phenomenon)` | 그 수목원에서 고를 수 있는 종 |
| `forecast(...)` | 기능 1: 개화일 예측과 범위 |
| `overlap(...)` | 기능 2: 축제 기간과 꽃 시기가 겹칠 가능성 |
| `ranking(...)` | 기능 3: 축제 기간에 맞는 종 추천 |
| `revision(site, species, year)` | 기능 4: 지난 해를 채택된 기준일(지금은 4월 15일)로 되돌린 예측과 실제 날짜 |

- 옛 이름(`list_sites` `list_species` `predict_date` `festival_overlap` `recommend_species`)도 같은 함수를 가리키는 별칭으로 파일 끝에 남겨 두었다
- 그래서 화면 코드는 고치지 않아도 그대로 돈다
- 저장소 어느 폴더에 두어도 위로 올라가며 `reports/tables`와 `reference`가 있는 곳을 찾아 돈다
- `data/processed/service`에 표 6개(combo_stats history bloom_pairs gaps shift decision)가 다 있으면 정제본 판 아니면 집계표(임시) 판이다
- 반환값의 source로 알 수 있다
- m1과 m1_inputs는 M1이 채택됐을 때만 쓴다
- revision은 기능 4만 읽는다
- 이 표가 없거나 비어 있으면 기능 4만 NOT_SUPPORTED로 답하고 다른 기능은 그대로 돈다
- 정제본 판에서 기능 2의 대표값(headline)과 기능 3의 적합도는 지난 해마다 실제로 겹쳤는지 센 값이다("N해 중 M해 겹침")
- 확률 곡선과 가장 좋은 기간은 분포 근사다
- 집계표 판은 개화시작이 정규분포를 따른다고 본 근사다
- 화면 개발용이다
- 기능 1~4는 예외를 던지지 않고 언제나 dict를 돌려준다
- 실패하면 ok가 False이고 code와 한글 message가 있다
- source와 warnings(빈 목록)도 늘 있다
  - 코드: UNKNOWN_SITE UNKNOWN_SPECIES UNKNOWN_PHENOMENON NO_DATA TOO_FEW_YEARS NOT_SUPPORTED BAD_DATE BAD_DAYS BAD_LENGTH BAD_LEVEL BAD_SCENARIO BAD_YEAR NO_CANDIDATE INTERNAL_ERROR
- 화면 쪽에서 확인할 것
  - INTERNAL_ERROR: 예상하지 못한 오류가 나도 화면이 멈추지 않게 이 코드로 돌려준다
  - 처음 정한 목록에 없던 코드다
  - `ranking`의 순위표에 최근5년_겹침 열을 더했다(정제본 판 "5해 중 4해" 꼴)
  - 참고 열이고 순위에는 쓰지 않는다
  - NO_CANDIDATE: `ranking`은 후보가 하나도 없을 때뿐 아니라 모든 후보의 적합도가 0일 때(12월처럼 꽃 철이 아닌 기간 너무 큰 겹침 기준 일수)도 이 코드로 답한다
  - 적합도 0인 순위표는 돌려주지 않는다
  - BAD_DATE: `overlap`과 `ranking`의 날짜는 `forecast`의 연도와 같이 2009~2030년만 받는다
  - 범위 밖이면 이 코드로 답한다
  - 이름(수목원 종 현상 lead)은 맥에서 복사해 자모가 풀린 한글(NFD)로 와도 받는다
  - 반환값에는 모은 꼴(NFC)로 적는다
  - `revision`은 새로 더한 함수이고 옛 이름이 없다(개화만 받는다)
  - 반환 키: ok site species phenomenon stage year ref ref_doy ref_date state base revised actual_doy actual_date years warnings source
  - ref는 기준일 이름이고 state는 그날까지 본 앞 단계다(앞 단계 없음 꽃눈파열 봄 개화시작 봄)
  - base는 기준 모델이고 revised는 M2다
  - 둘 다 method pred_doy pred_date interval(level low_doy high_doy low_date high_date) error_days를 담는다
  - error_days는 예측과 실제 날짜의 차이고 두 예측 모두 그 앞 해들의 기록만으로 낸 값이다
  - years는 그 조합에서 되돌려 볼 수 있는 해다
  - 그해 기준일에 이미 핀 조합과 예측이 없는 해는 NO_DATA로 답하고 years를 함께 준다
  - 새 오류 코드는 없다
- 꽃이 핀 날은 개화시작 <= 날 <= 낙화90~100%로 센다(A의 집계와 같다)
- 하루 창 적중률은 A의 표와 조금 다를 수 있다
- A의 `eda_fixed_day_hit.csv`는 날짜숫자를 고정하고 함수는 달과 날을 고정한다(윤년이 아닌 해의 2월 29일은 2월 28일로 본다)
- 윤년에는 같은 달과 날의 날짜숫자가 하루 밀린다
- `tests.py`가 A와 같은 조합 수를 참고로 적는다
- 2월 말 예측(lead="2월 말")은 M1이 채택되고 그해 2월 기온이 m1_inputs에 있을 때만 그해 기온을 쓴다
- 지금은 2009~2025년 입력만 있어 2026년 이후는 계획 값으로 답하고 경고를 단다
- lead는 계획 2월 말 시나리오 중 하나다
  - 기온 가정(temp_scenario)을 주면 lead와 상관없이 시나리오로 답한다(단풍은 기온 가정을 반영하지 않는다)
  - lead="시나리오"인데 기온 가정이 없으면 계획 값으로 답하고 경고를 단다
  - `overlap`은 2월 말 예측을 쓰지 않는다
  - lead="2월 말"이면 계획 값으로 답하고 경고를 단다
  - 목록에 없는 값이면 계획 값으로 답하고 경고를 단다

## 8. 점검(tests.py)

- 계약(반환 키 표의 열 오류 코드) 값의 범위 순서와 단조성 지난 해 다시 세기 내부 오류 처리를 모든 조합에서 본다
- 정제본 판에서는 A의 표와 맞춰 본다(설계서 10절)
- 조합 통계가 A의 표와 같으면 하루_적중률 다시 세기와 8년 이상 조합 목록이 어긋날 때 실패로 센다

- 기능 4는 `revision.csv`의 모든 줄에서 반환 키와 범위의 순서와 표의 값과 기능 1의 실제 날짜를 본다
- 이 표가 없거나 비어 있으면 기능 4는 오류 코드만 본다
